# hub-driver · 在 AI Hub 里调度别的模型

一句话：**负责人管目标、接口和验收，大活派出去、小活自己干；派之前按第 1 节选路，回执里写明走了哪条路和理由。**

## 命令入口

AI Hub 启动的会话里有环境变量 `CLAUDE_HUB_CLI`，指向 Hub 数据目录 `team` 子目录下的 `hub` 命令（Windows 上是 `hub.cmd`）。同目录还有 `hub-team` 命令，等同 `hub team …`。

| 命令 | 干什么 |
|---|---|
| `hub help` | 看全部子命令和参数 |
| `hub session new --kind <kind> --task-file <任务书.md>` | 新开一个会话（可加 `--model`、`--effort`、`--account`） |
| `hub models --kind <kind>`、`hub accounts` | 查可用模型、账号和额度 |
| `hub-team status` | 看团队、成员状态和待处理消息 |
| `hub-team propose --plan-file <计划.json>` | 招成员 |
| `hub-team send --to m1 --message-file <消息.md>` | 给成员发消息 |
| `hub-team read --id <消息编号>` | 读长消息原文 |
| `hub-team dismiss --member m1` / `restart --member m1` | 放人 / 重启卡住的成员 |

- PowerShell 里调用时命令前加 `&`。
- 多行内容一律先写成 UTF-8 文件，再用 `--message-file` / `--task-file` 传；批处理会截掉换行后的内容。
- **缺能力不绕路**：要做的事先查 `hub help`；Hub 确实没有这项能力，就向用户说明「Hub 缺 X 能力」，不改用后台裸命令行另起不受 Hub 管理的会话。

## 1. 选路：从上往下，命中即停

| # | 情况 | 走哪条路 |
|---|---|---|
| 1 | 用户点名了后端、模型或账号 | 照点名走；起不来时先用最接近的后端推进，并在汇报首句写明换了谁、为什么 |
| 2 | 短时只读：读码摘要、单点核实、审查一段改动 | 负责人自己的**原生子 Agent**（不占侧栏） |
| 3 | 赛马，或同一件事派 2 人以上 | **侧栏成员**（`race` 计划） |
| 4 | 要改文件、预计超过 10 分钟、或任务书很长 | **侧栏成员** |
| 5 | 拿不准 | **侧栏成员**（用户能在侧栏看到、能追问） |

负责人自己做：读回执、抽查 1–2 处、改一两行、跑一条确认命令。小活派出去反而更慢更贵（成员冷启动要重新读上下文）。

## 2. 后端怎么选

| kind（别名） | 适合 | 备注 |
|---|---|---|
| `claude` | 界面、写作、架构取舍、需要判断的活 | 默认首选；Hub 能对它强制只读与危险动作拦截 |
| `codex` | 靠测试或数字验收的实现、长调试、只读审查 | 起在沙箱里 |
| `gemini`（`antigravity`、`agy`） | 交叉审查、看截图、读长文档 | 只读只能靠任务书约束 |
| `qwen`、`glm`、`kimi` | 第二意见、批量阅读 | 需要你自己的对应账号或套餐 |
| `deepseek-claude`、`deepseek-acp` | 批量阅读、打分 | 官方 API 按量计费：用前先估花费并告诉用户 |

- 只有 `claude` / `codex` / `gemini` 能指定 `account`；其余后端沿用 Hub 新建会话的默认配置。
- 模型和思考强度：不写就用 Hub 默认；用户点名才写。可选值以 `hub models --kind <kind>` 的实时输出为准。
- 计划里的账号、模型是申请值，创建后用 `hub-team status` 核对实际生效值。

## 3. 组队流程（侧栏成员）

1. **开工**：`hub-team status` 确认能连（无输出、超时、报错都不算成功）；`hub accounts` 看额度。
2. **招人**：写计划文件后 `hub-team propose --plan-file 计划.json`：
   ```json
   {"goal":"这批人一起要完成什么",
    "members":[{"role":"分工（边界）","task":"任务书路径","kind":"claude","cwd":"<项目目录>","title":"侧栏显示名",
                "access":"read（审查类成员才写）"}]}
   ```
   - 成员 `cwd` 是 git 仓库主目录且不是只读成员时，Hub 会从主干替它建独立 worktree 和分支，开工消息和 `status` 里给路径与基线 SHA；不需要时写 `"worktree": false`。
   - 写清每人选这个后端的理由。招人失败（账号不存在、额度耗尽）会当场报错，先看原因再改计划，不原样重试。
   - 新任务优先复用同领域、还在队的成员；用不上的及时 `dismiss`。
   - 只想开一个会话给用户或别的会话用、不进验收流程时，用 `hub session new`。
3. **派活与汇报**：`hub-team send --to m1 --message-file 消息.md`。成员空闲时送达；要改它正在做的事加 `--interrupt`，并说清哪条作废。成员默认留言、不叫醒负责人；卡住、失败、要拍板时加 `--wake`，交付时加 `--deliver`。
4. **验收**：成员交 300 字以内的回执 → 负责人派一个新的原生子 Agent 独立审（作者不审自己），只回「通过 / 不通过、必须改的点、建议亲自看的 1–2 处」→ 负责人抽查这 1–2 处，界面改动在真实页面截图核对。
5. **收尾**：交付处理完后 Hub 让成员离队休眠；返工直接 `send` 叫回原成员。
6. **负责人少说话**：成员消息不逐条转述，只在里程碑、坏消息、要用户拍板时汇报；没有变化时不刷屏。

赛马计划最小样例：

```json
{"goal":"修登录竞态","race":true,"task":"同一道题的任务书路径","members":[{"kind":"claude"},{"kind":"codex"},{"kind":"gemini"}]}
```

全员交齐后 Hub 跑测试出成绩单、叫醒负责人一次；负责人派不参赛的子 Agent 当裁判，抽查后让胜者合入。

## 4. 成员权限

- 默认可写。审查、复核类成员在计划里写 `"access":"read"`。
- 只读的保证程度：Claude 系由 Hub 拒绝写文件（临时目录除外）；Codex 起在只读沙箱；其余后端只靠开工消息里的约定，回执里要注明。
- 以下 5 类危险动作，Claude 系成员由 Hub 硬拦，其余后端靠约定先停下交负责人判断：① 推送、合入或改写 master/main；② 关闭、重启或 kill 正在使用的 Hub；③ 删除任务目录以外的文件；④ 改 Hub 数据目录里的配置与状态；⑤ 读取或使用按量计费的 API Key。
- 被拦时 Hub 叫醒负责人说明谁、什么命令、为什么；负责人能定就用 `hub-team pass --to m1` 放行一次，不可逆或对外的先问用户。

## 5. 护栏

- **防繁殖**：经 `hub` 建出的会话最多到第 2 层；成员不能再招 Hub 成员。
- **人数以配置为准**：上限看 Hub 设置里的团队配置，不按文字自我限流；但不为了显得忙开新成员。
- **额度**：起成员时账号余量偏低或本机内存不足，Hub 会留言提醒（不拦人）——让闲着的成员 `dismiss`，新成员换余量多的账号。同一账号多开会话共享额度。
- **不悄悄换成按量计费**：额度满先换同后端别的账号；按量 API 用前先估「调用次数 ×（输入、输出 token）× 单价」，写进汇报，金额较大先问用户。
- 依赖目录是目录链接（junction）的 worktree 里不要 `npm ci` / `npm install`。

## 6. 出错与续跑

- **成员起不来**：先看 `hub-team status` 里的状态和失败提示里给的「终端最后一屏」文件；`restart --member` 可以按原配置重新启动；仍起不来就换后端补派，并在汇报里写明。
- **结果不明**：`hub` 命令超时，用同一个 `--key` 重试，不会重复建会话或发消息。
- **Hub 重启后**：成员可能显示 missing，`restart --member` 接回原历史；叫醒后看 `undelivered` 确认消息真的送到了。
- **长任务**：超过约 2 小时的任务在任务目录维护一张进展卡（目标、已定事项、当前步骤、关键提交与路径），换号或压缩后先读卡再继续。
